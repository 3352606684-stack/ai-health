## 修复：对话内容溢出屏幕（重要布局坑）

**现象**：发几条消息后，新消息出现在视口外，`overflow-y: auto` 不生效。

**根因**：`Portallayout.vue` 的 `.main` 写的是 `flex: 1 1 auto`。basis 为 `auto` 时，flex item 的基准高度等于内容高度，内容一多 `.main` 就被撑高（实测 779 → 1092），子元素的滚动容器永远不触发（`.messages` 的 clientH 跟着从 537 涨到 849）。

**修法**：
1. `Portallayout.vue` `.main`：`flex: 1 1 auto` → **`flex: 1 1 0`** + `min-height: 0`。basis 设 0 后高度只由容器剩余空间决定。
2. `Chat.vue` `.ai-chat`：补 `height: 100%` + `overflow: hidden`。
3. 窄屏 `.panel`：不能写 `min-height: 68vh`（左栏高 + 68vh 会超容器把输入框顶到页脚下面），改 `flex: 1 1 0; min-height: 0`。

**验证**：11 轮对话后 messages h=537 不变、scrollH=1917、scrollTop=1380（=1917-537，正好底部）；`.main` 稳定 779；`/portal/home`、`/portal/diary`、`/portal/library`、`/back/dashboard` 均未被影响。

**通用规律**：任何「固定高度外壳 + 内部滚动区」的布局，链路上每一层 flex item 都要 `flex: 1 1 0` + `min-height: 0`，只要中间一层是 `1 1 auto`，滚动就会失效。

## AI 咨询页：会话历史对接（新建归档 / 点击恢复）

文件：`demo/frontend/src/views/portal/Chat.vue`

**数据结构**
- 一条历史 `{ id, title, time, messages:[] }`，`sessions` 按最近活跃倒序
- `messages` 是活动数组，`sessions[i].messages` 是归档快照，**互为拷贝**（两边会各自被改）
- `currentSessionId`（null = 未入库）+ `dirty`（入库后又发过消息）两个标记决定是否写回
- `MOCK_SESSIONS` 预置 2 条演示会话（失眠 / 室友矛盾），`USE_MOCK` 为 false 时为空

**函数**
- `makeTitle(list)`：取第一条 user 消息，>12 字截断加省略号，没有则「新的对话」
- `archiveCurrent()`：空白会话返回 false；已存在则原地更新后 unshift 置顶，否则新建 id 插最前；返回是否写入
- `newSession()`：`dirty ? archiveCurrent() : false` → 清空 → `ElMessage.success('已保存到会话历史')`；确认框文案改为「当前对话会保存到左侧「会话历史」…」
- `openSession(id)`：sending 拦截 → `dirty && archiveCurrent()` → 拷贝 `target.messages` → dirty=false
- `send()` push 用户消息后置 `dirty = true`

**样式**：`.history-list` 补 `flex: 1 1 auto`（条目多时能滚）；窄屏不再 `display:none`，改整行 `flex: 1 1 100%` + `max-height:132px`，`.panel` 补 `min-height:320px`。

**验证**：`tools/verify-chat-history.js` 16 项全通过 —— 初始 2 条 / 新建后 3 条置顶且无高亮 / 恢复 5 条气泡 / 未改动再新建不重复 / 来回切会话内容不丢 / 无 JS 报错（唯一 404 是浏览器自动请求 favicon.ico）。

## 修复：历史会话「聊不进去」+ 实时写回

用户反馈「查看历史对话不能在历史对话框里面对话」。实测发送本身是通的，真正的问题是**历史只在切走/新建时写回**，在历史会话里聊半天左栏时间不动、不置顶，看起来像只读。

改动（`Chat.vue`）：
1. `send()` 的 `finally` 里加 `archiveCurrent()` —— 每轮问答落地就写回历史（时间刷新 + 置顶 + 高亮）。
2. `archiveCurrent()` 更新已有会话时保留旧标题 `{ ...old, ...snap, title: old.title }`，否则聊到第 N 轮标题会变成最后一句内容。
3. 新增 `inputEl` ref，`openSession()` / `newSession()` 结束后 `nextTick(focus)`，窄屏下浏览器顺带把输入框滚进视口。
4. `newSession()` 确认文案改为「当前对话已保存在左侧「会话历史」…」，去掉重复的 `ElMessage.success`。

验证（`tools/verify-chat-history.js` 重写）：18 项全通过 —— 打开历史气泡 3 条 / 高亮正确 / 自动聚焦 / 历史里 Enter 发送 5 条 / 标题不变且置顶时间 23:35 / 切走再切回内容一致 / 新会话首条消息即入列表并高亮 / 空白不占条目 / 无报错。

## 决策：历史会话改为「只读浏览」

用户拍板：查看历史会话时输入框禁用，不能接着聊。理由是接大模型后上下文 token 成本 —— 无状态 API 每轮都要重发 messages，历史越长越贵；只浏览则零请求零 token。

实现（`Chat.vue`，三不动原则）：
- 新增 `viewingId`（非 null = 浏览中）、`viewMessages`（副本）、`isReadOnly` computed、`displayMessages` computed
- 模板渲染 `displayMessages`；浏览时 **不碰** `messages` / `currentSessionId` / `dirty`，也不调 `archiveCurrent()`
- `openSession(id)`：点当前对话那条 → `exitPreview()`；点其他 → 只填 viewMessages
- `exitPreview()`：清 viewingId/viewMessages + focus 输入框
- 出口两个：点 `is-active` 那条，或点「返回当前对话」
- UI：输入框 `:disabled` + placeholder「历史会话已结束，不能继续对话」+ `.readonly-bar` 提示条（"正在浏览历史会话，仅可查看"）+ 底部「仅浏览模式」；`.history-item.is-viewing` 深米色 + 左侧橙条，与 `is-active` 区分
- `send()` 开头加 `isReadOnly` 拦截（双保险，防 Enter/脚本）

验证（`tools/verify-chat-readonly.js`）：23 项 —— 只读时输入框/发送按钮均 disabled、提示条与 placeholder 正确、强点发送气泡数不变、退出后解禁且内容回到当前会话并 focus、点当前对话那条也能退出、只读时新建正常、**api 请求数 0**、无报错。
截图：`previews/chat-history-readonly.png`。

文档：`项目认知梳理.md` 3.14 新增「坑 7：历史只读浏览」+ 速查卡 ⑩ 更新；并记下"若放开续聊，正确做法是滑动窗口+摘要，而非整段重发"。
